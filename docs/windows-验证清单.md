# Windows 手动验证清单

下面这些改动我只在 Linux（xvfb 虚拟显示 + Playwright 驱动 Electron）下验证过。Windows 上的真实窗口、系统保存对话框、打包后的 exe，请你手动过一遍。预计 10 分钟。

## 0. 准备

在 PowerShell 里（国内网络先设置镜像，见 README）：

```powershell
git checkout game-v0
git pull
npm install
npm start
```

想测"第一次启动"的体验（规则页自动弹出、没有存档），先删掉本游戏的本地数据再启动：

```powershell
Remove-Item -Recurse -Force "$env:APPDATA\K线策略游戏"
```

> 如果是 `npm start` 运行的源码，Electron 的数据目录名可能是 `kline-simulator`（取自 package.json 的 `name`）而不是 `K线策略游戏`。两个目录都删最保险：`$env:APPDATA\kline-simulator`、`$env:APPDATA\K线策略游戏`。

## 3. 导出记录（最重要的一项：真实的系统保存对话框）

先打完一局（想快一点：每回合直接点"结束回合"，不交易也行，20 回合约 45 秒），在结算界面点"💾 导出本局记录"。

| # | 操作 | 期望 | 结果 |
|---|------|------|------|
| 3.1 | 点导出 | 弹出 Windows 的**"另存为"对话框**，标题"导出本局记录" | |
| 3.2 | 看默认目录 | 是你的"**下载**"文件夹 | |
| 3.3 | 看默认文件名 | `kline-game-seed<数字>-<14位时间>.json`，文件类型过滤为 JSON | |
| 3.4 | 点保存 | 结算卡片里出现 `✔ 已保存到：<完整路径>` | |
| 3.5 | 打开保存的文件 | 是合法 JSON：有 `seed`、`gameVersion`、`turns`（20 项，每项有 `durationMs`/`research`/`orders`）、`result`、`truth` | |
| 3.6 | 再点导出，在对话框里点"取消" | 显示"已取消导出"，不产生文件 | |
| 3.7 | 再点导出，保存到同一个文件名 | Windows 询问是否覆盖；选是后正常写入 | |
| 3.8 | 再点导出，选一个没有写权限的位置（如 `C:\Windows`） | 显示 `✘ 保存失败：…`，游戏不崩溃 | |
| 3.9 | 中文路径/带空格路径 | 例如保存到 `D:\我的 文档\` 能正常写入 | |

可选：在 Node 里校验记录能重放（不需要 electron）：

```powershell
node -e "const R=require('./js/game/record.js');const r=R.replay(require('<导出文件的绝对路径>'));console.log(r.result.totalAssets)"
```

输出应与结算界面显示的总资产一致。

## 5. 打包后的 exe

```powershell
npm run build
```

对 `dist\K线策略游戏.exe` 重复第 1–4 项，另外确认：

- 双击能启动（SmartScreen 提示按 README 处理）。
- 窗口标题和任务栏图标是"K线策略游戏"。
- 退出后没有残留进程。
- 便携版的数据目录可能与 `npm start` 时不同——这是正常的，意味着 `npm start` 的存档不会出现在 exe 里。

## 我没法在 Linux 上验证的部分（汇总）

1. 真实的 Windows 标题栏、关闭按钮（xvfb 里没有窗口管理器，没有标题栏）。
2. 真实的系统保存对话框：我在测试里把 `dialog.showSaveDialog` 替换成了桩，只验证了"传给对话框的参数正确（默认目录=下载、默认文件名、JSON 过滤）"以及"用户选定/取消/写入失败三种结果的处理"。
3. F11/Esc 在真实窗口管理器下的全屏行为（我只验证了 `isFullScreen()` 状态切换）。
4. 打包（`npm run build`）与便携版 exe。
5. 中文路径、系统"下载"文件夹被重定向（OneDrive）时的表现。
